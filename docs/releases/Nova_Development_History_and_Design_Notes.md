# Nova 开发版本树与设计细节记录

> 本文档用于记录 Nova 从当前阶段开始到 v2.7.2 的主要版本演进，以及开发过程中确定下来的关键设计细节。  
> 这份记录适合放在仓库中，例如 `docs/DEVELOPMENT_HISTORY.md` 或 `docs/DESIGN_NOTES.md`。

# 一、版本树

## 0. 初始基础版本

在后续版本迭代之前，Nova 已经具备了一个桌面工作台的基础形态：

- Electron + TypeScript 桌面应用基础架构
- 左侧主导航
- 首页
- 文件管理器
- AI 助手
- 待办中心
- 设置页
- Monaco Editor 编辑器集成
- Markdown 文件查看与编辑
- OpenAI Compatible API 配置入口
- 基础 Todo 管理
- Windows 打包配置

这一阶段的 Nova 更像是一个「功能集合」：

```text
首页
文件管理
AI 助手
待办中心
设置
```

后续迭代的核心目标，是把这些功能逐步打通成完整的项目工作流：

```text
工作区 / 项目
→ Markdown 文档
→ AI 处理
→ 生成待办
→ 首页追踪
→ 项目概览
→ 版本安全
→ 命令面板
→ 模板系统
```


## v2.1.1 - AI 调用兼容性修复

这一版主要解决国产 OpenAI Compatible 接口兼容问题。

### 修复

- AI 聊天流式失败后自动降级为普通非流式请求
- 兼容用户填写完整 Base URL 的情况，例如：
  - `/v1`
  - `/v1/chat/completions`
- Markdown 页 AI 操作前重新读取最新 AI 配置
- AI 页面发送消息前重新读取最新 Provider 配置
- 补齐主进程 / 渲染层 AI IPC 封装

### 设计目标

让 Nova 不只兼容标准 OpenAI API，也能尽量兼容国内各类中转、聚合和国产模型服务。

## v2.1.2 - AI 配置同步修复

这一版主要修复「设置页保存了模型，但 AI 助手页没有同步」的问题。

### 修复

- 设置页保存 Provider 后，AI 助手页会刷新配置
- AI 助手页模型下拉框自动加入设置页保存的模型
- AI 助手页显示当前默认 Provider / 模型
- AI 状态条显示当前 Provider 和模型
- 聊天、AI 工具、Markdown AI 操作都在发起请求前读取最新配置

### 设计目标

AI 配置作为全局能力，必须在所有页面保持一致，避免出现：

```text
设置页显示已配置
AI 助手页仍然为空
文件管理器 AI 操作读取旧配置
```

# 二、开发设计细节

## 1. 工作区与项目的关系

Nova 中「项目」本质上是一个本地文件夹。

用户操作时使用「打开工作区」，Nova 内部将这个工作区理解为一个项目。

```text
文件夹 = 物理存储位置
项目 = Nova 对这个文件夹的组织和理解
```

示例：

```text
我的项目/
├── README.md
├── 产品方案.md
├── 会议纪要.md
└── .nova/
    ├── project.json
    ├── todos.json
    ├── activity.json
    └── history/
```

这样设计的原因：

- 用户容易理解
- 数据本地优先
- Markdown 文件不被锁死
- 可以被 Git / OneDrive / iCloud / 坚果云同步
- 整个项目文件夹可以直接迁移
- `.nova` 只保存 Nova 的项目元数据

---

## 2. `.nova` 目录设计

Nova 在每个工作区中创建 `.nova` 目录，用于保存项目级数据。

```text
.nova/
├── project.json
├── todos.json
├── activity.json
└── history/
```

各文件职责：

| 文件 / 目录 | 作用 |
|---|---|
| `project.json` | 项目名称、描述、创建时间、更新时间 |
| `todos.json` | 当前项目的 Todo、分类、状态 |
| `activity.json` | 当前项目活动记录 |
| `history/` | 当前项目中文档的历史版本备份 |

设计原则：

```text
用户文档保持开放
Nova 元数据集中在 .nova
项目可以整体复制和迁移
```

---

## 3. Todo 按项目隔离

早期 Todo 是全局数据，后来改为项目级数据。

最终设计：

```text
项目 A/.nova/todos.json
项目 B/.nova/todos.json
项目 C/.nova/todos.json
```

这样可以保证：

- 项目 A 的任务不会出现在项目 B
- 首页任务统计基于当前项目
- 项目概览统计准确
- AI 生成的任务写入当前项目
- Ctrl+K 搜索 Todo 只搜索当前项目

这是项目概览页成立的前提。

---

## 4. 文件管理器标签页设计

文件管理器的标签页参考了 VS Code 的设计模式。

### 预览标签

当用户在文件树中单击文件时，文件以「预览标签」打开。

特点：

- 当前只是快速查看
- 再点击其他文件时，会复用这个预览标签
- 不会在标签栏中越堆越多
- 适合快速浏览文件内容

### 常驻标签

当用户进入编辑状态后，标签会变成常驻。

触发方式包括：

- 修改文件内容
- 双击文件
- 执行明确打开操作
- 从命令面板打开并编辑
- 需要保留上下文的操作

常驻后：

- 不会被下一个预览文件替换
- 可以在多标签之间切换
- 用户可以长期编辑多个文档

### 设计原因

如果每次单击文件都创建一个永久标签，文件管理器很快会出现大量无用标签。  
参考 VS Code 的预览标签模式后，Nova 可以同时满足：

```text
快速浏览
长期编辑
标签栏不混乱
```

---

## 5. Markdown 编辑模式

文件管理器中的 Markdown 支持多种工作状态：

- 编辑
- 预览
- 分屏

设计目标：

```text
写作时专注编辑
检查效果时切换预览
整理文档时使用分屏
```

工具栏中同时提供 AI 操作：

- AI 总结
- 生成大纲
- 改写选中
- 问当前文档
- 生成待办

这些功能不是独立 AI 聊天，而是绑定当前文档上下文。

---

## 6. AI 上下文设计

Nova 的 AI 功能分为几种上下文级别。

### 普通 AI 聊天

AI 助手页中的对话，不一定绑定当前文档。

### 当前文档 AI

文件管理器中触发的 AI 操作，会自动携带：

- 当前文件路径
- 当前文档内容
- 当前选中文本
- 用户问题

例如「问当前文档」会基于当前 Markdown 内容回答。

### 项目级 AI

项目概览中的 AI 操作，会携带：

- 项目名称
- 项目描述
- 最近文档
- 当前 Todo 状态
- 最近活动
- AI 配置状态

用于生成：

- 项目总结
- 本周计划
- 项目风险分析

### 设计原则

AI 不应该只是一个聊天框，而应该理解用户当前正在处理的对象：

```text
当前文档
当前任务
当前项目
当前工作区
```

## 7. AI Provider 配置设计

Nova 支持 OpenAI Compatible API，而不是只绑定某一家模型。

配置项包括：

- Provider 名称
- Base URL
- API Key
- 默认模型
- 是否启用当前供应商

设计时重点处理了国产模型兼容问题：

- Base URL 可以填写 `/v1`
- 也可以填写完整 `/v1/chat/completions`
- 流式请求失败后自动降级非流式
- 每次 AI 操作前重新读取最新配置
- 设置页保存后通知其他页面刷新
- AI 未配置时引导到设置页

设计目标：

```text
允许用户接入 DeepSeek、通义千问、Kimi、智谱、硅基流动、小米 MiMo、Ollama、自定义中转服务等。
```

## 8. 不使用原生 prompt()

Electron 35 环境中原生 `window.prompt()` 不可用，会报：

```text
prompt() is not supported.
```

因此 Nova 统一使用自定义弹窗处理输入。

包括：

- 问当前文档
- 新建文档
- AI 模板主题
- 恢复确认
- 删除确认

设计原则：

```text
桌面应用不依赖浏览器原生弹窗
所有交互统一使用 Nova 自己的 UI 组件
```

## 9. AI 生成 Todo 设计

AI 生成 Todo 的流程不是直接写入，而是：

```text
读取当前文档
→ AI 提取可执行任务
→ 弹出确认列表
→ 用户确认
→ 写入当前项目 .nova/todos.json
→ 通知待办页刷新
```

这样可以避免：

- AI 生成错误任务直接污染数据
- 用户不知道创建了哪些任务
- 重复点击导致重复创建
- 待办页仍显示旧缓存

Todo 会记录来源：

- 来源类型
- 来源文档路径
- 来源相对路径
- 来源标题
- 来源行号（预留）

设计目标：

```text
任务不是孤立的，而是能回到它产生的文档。
```

首页从「入口页」改为「今日工作台」。

首页重点展示：

- 未完成任务

- AI 状态

用户每天打开 Nova 时，不应该先思考去哪个页面，而应该直接看到：

```text
今天要做什么
最近在写什么
当前项目状态如何
AI 是否可用
```

## 11. 项目概览页设计

## 12. 版本历史设计

文档历史版本保存在：

```text
当前工作区/.nova/history/
```

版本历史包含几种来源：

- 手动保存版本
- 自动保存版本
- AI 改写前备份
- AI 插入前备份
- 恢复前自动备份

后来为了避免「只是查看也生成备份」的问题，加入了「预览」功能。

最终区分：

```text
预览 = 查看，不改变当前文档，不生成备份
恢复 = 覆盖当前文档，恢复前自动备份
删除 = 删除历史版本，不影响当前文档
```

设计目标：

```text
AI 修改文档可以大胆使用，因为永远可以回退。
```

## 13. Ctrl+P 与 Ctrl+K 的分工

Nova 中两个快捷键有明确分工。

| 快捷键 | 定位 | 作用 |
|---|---|---|
| `Ctrl+P` | 快速打开文件 | 搜索并打开当前工作区文件 |
| `Ctrl+K` | 全局命令面板 | 搜索命令、AI、模板、Todo、文件和文档内容 |

简单理解：

```text
Ctrl+P = 找文件
Ctrl+K = 找功能 / 做事情
```

这参考了 VS Code 的常见交互习惯。

## 14. 命令面板设计

## 16. AI 模板生成设计

v2.7.1 后，模板系统支持 AI 填充。

流程：

```text
选择模板
→ 输入主题 / 需求
→ AI 根据模板结构生成完整 Markdown
→ 写入文件
→ 自动打开编辑器
```

AI 生成失败时，系统会降级为普通模板创建，避免用户无法继续。

设计目标：

```text
模板提供结构
AI 提供内容
Nova 负责把内容落地成文档
```

## 17. 模板创建弹窗布局设计

v2.7.2 对模板创建弹窗进行了重新设计。

最终布局：

```text
统一大弹窗
├── 左侧：模板选择
└── 右侧：创建配置
    ├── 文件名
    ├── 创建方式
    ├── 主题 / 需求
    └── 项目信息
```

底部统一放置：

- 取消
- 创建

设计原因：

之前右侧配置面板像是「漂浮在外面」，视觉上与主弹窗脱节。  
新版把选择模板与创建配置放在同一个容器中，形成一个完整的创建流程。

## 19. 本地优先设计

Nova 的核心方向是本地优先。

这意味着：

- 用户文档就是普通 Markdown 文件
- 项目数据保存在本地 `.nova`
- AI 配置保存在应用配置中
- 不强制账号体系
- 不依赖云端服务
- 用户可以自己决定是否用 Git / 云盘同步

设计原则：

```text
数据属于用户
文件可迁移
离开 Nova 也能打开 Markdown
```

# 三、当前产品定位总结

Nova 当前可以被定义为：

> 一个本地优先的 AI 项目工作台。

它不是单纯的 Markdown 编辑器，也不是单纯的 Todo 工具，而是把：

```text
文件夹
Markdown 文档
AI 助手
项目待办
版本历史
项目概览
命令面板
模板系统
```

连接成一个完整工作流。

核心价值是：

```text
让用户在本地项目中沉淀文档，
用 AI 理解和生成内容，
把内容转化为待办，
再通过首页和项目概览持续推进。
```
